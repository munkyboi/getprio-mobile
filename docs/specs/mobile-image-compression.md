# Selected image uploads

Profile photos and booking manual-payment receipts are prepared on the device before upload. The shared helper uses the Dart `image` library in a worker isolate. Before every profile-photo or payment-proof upload attempt, including retries, the repository fetches authenticated `GET /api/account/image-upload-policy` (versioned to `/api/v1/account/image-upload-policy`). The response `{maxImageBytes: integer}` comes from the Platform Dashboard effective image limit. Files already at or below that limit are passed through unchanged. Larger supported JPEG/PNG/WebP files are decoded, oriented, flattened on white and encoded to JPEG, trying long edges 2000/1600/1280/1024 and quality88/80/72. It preserves aspect ratio and never enlarges the image. Converted filename and content type match the encoded bytes; original gallery files are untouched.

Picker sizing limits initial native selections to2400px per side. The helper bounds source files to8MB, still images to24MP, and rejects files that cannot fit at its resolution/quality floor. The server's configurable upload policy remains authoritative. The policy endpoint uses `Cache-Control: no-store`; mobile does not cache it or fall back to a fixed/stale value. Invalid or unavailable policy reads stop the upload with retry guidance, bounded to20seconds. Selected original bytes stay available until upload so policy changes between selection and submission or retries can be honored. A server limit change during an in-flight upload is still enforced by the server; a new attempt fetches the new limit. This mobile integration requires the policy endpoint deployed before device rollout. Unsupported, unreadable or excessively complex files receive local guidance rather than an over-limit upload.

Manual-payment receipts remain private and pending vendor review. Compression does not change eligibility, payment verification or submission state. Local tests cover byte limits, naming/MIME, orientation, transparency, invalid inputs and existing payment/profile flows. Physical-device upload and receipt readability acceptance remains separate from build/install evidence.
